# Issue body template

Use this body when an AI creates tickets. For a local fallback, copy to a new file in tasks/; reconcile into GitHub later.

## Outcome

What a user or developer can do when this is complete.

## Acceptance criteria

- [ ] Observable behavior, including important failure/empty states.
- [ ] Relevant validation demonstrates it works.

## Scope and exclusions

Expected components/files; what this ticket must not expand into.

## Dependencies

Issue/PR URLs plus prerequisite outcomes; write None if independent. State whether required work is merged and which base branch to use.

## Contracts and context

Links to brief, architecture, research, and exact interface/code/schema references. Identify proposed versus agreed interfaces.

## Validation

Exact commands or reproducible manual steps and expected results. Record prerequisites and any external resource needs.

## Coordination

- Task ID / phase: allocated during organization.
- Session owner: unassigned until the user assigns it.
- Shared-file/environment conflicts: list or None.
- Priority: must / should / stretch.

## Assignment comment (post on start)

Session nickname; worktree; task branch; base commit; scope; intended checks.

## Handoff comment / PR evidence

- Issue and task ID:
- Session / branch / PR / commit:
- Changed behavior and acceptance criteria satisfied:
- Commands run and actual outcomes:
- Manual checks and observations:
- Skipped checks / blockers / limitations:
- Contract, env, migration, or dependency changes:
- Integration steps and next action:
